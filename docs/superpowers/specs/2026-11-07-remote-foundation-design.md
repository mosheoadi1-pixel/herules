## Deliverable
Two separately authenticated adults can pair, create sessions, independently approve a versioned agreement, deliver and acknowledge missions, submit written completions, review them once for points, exchange text, and see persisted notifications and history across browsers. Both participants have independent pause and irreversible stop controls. Only the pausing participant can release their own pause; stopping cannot be undone. Browser disconnects never acknowledge missions. Deadlines use backend timestamps and a single union-of-pauses interval. Scheduled missions become available through authoritative reads and realtime refresh. Changes to an agreement require two fresh approvals and suspend gameplay until approved.

## Security
Password hashing, opaque cookie sessions stored hashed, same-origin request protection, validated bounded inputs, rate limits, database transactions with row locking, role and pair ownership checks. Invitations are random, hashed, expire, single-use, and revocable. Responses exclude password/session/invite hashes and unrevealed secret missions. No sensitive browser/service-worker response caching. No media upload or push presented as implemented.

## Library and UI
Luxury burgundy/black/gold, responsive Hebrew-first RTL. Eight categories: challenges, timed missions, rewards, consequences, roleplay, anticipation, random events, secret missions. At least 160 distinct curated bilingual ideas with duration, intensity and boundary tags; filtering, favorites, recent-use avoidance, editable suggestions and custom missions. Consequences never attach to refusal, pause or stop. Dice and branching choices must be clearly optional, acknowledged gameplay. No placeholder duplication to inflate counts.

## Binding review refinements
- Adults self-attest at registration. One pair per account, exactly one wife and one husband, no self-pairing; one nonterminal session per pair. Invitation redemption uses a locked transaction and uniqueness constraints. Every user/revision approval and mission point award is unique in PostgreSQL.
- Mission state machine: wife creates draft, queues/schedules, sends or cancels; husband acknowledges pending missions, refuses without penalty, submits text only after acknowledgement; wife approves submitted work once or returns it for revision. Delivered terms are immutable: cancel and replace instead of editing. Every mission binds to an immutable agreement revision. Proposing replacement terms cancels unfinished missions; both users approve the new revision before new delivery. Stale approvals fail.
- A session starts its duration only after initial mutual approval. Agreement review and any participant pause freeze the session clock using one continuous suspension interval covering their union. Scheduled delivery freezes while suspended; absolute scheduled timestamps become eligible only after resume. Expiry is terminal; extension is allowed only before expiry/stop. No mission expiry in this foundation. Pause and stop remain available during review. Every mutation locks the session and evaluates server time, terminal state, active revision and pauses before changing gameplay.
- Use caller-supplied UUID idempotency keys with unique database constraints for mission creation and message submissions; repeat completion/review requests have no duplicate effects. Stop wins once committed: later gameplay transactions fail. Awards already committed remain history, never a penalty for stopping.
- Auth cookies: HttpOnly, SameSite=Lax, Secure in production, bounded expiry; logout revokes hashed server sessions. Mutations validate exact configured Origin; identity/roles come from the server session. Rate-limit registration, login, invitation attempts. SSE emits content-free invalidations and authenticates pair ownership; authorized reads supply data. Tokens are never placed in logs, history, referrers or inbox. Secret mission content is wife-only until explicit sending; pending secrets reveal only on delivery. Recipient history/inbox use generic metadata until then.
- Serve a root replacement worker with network-first navigation and old demo-cache cleanup; never intercept /api requests or cache authenticated data. Legacy worker only under /legacy/. Browser QA includes previously installed worker upgrade.
- Poll authorized state at most every five seconds as reconnect/scheduling fallback alongside SSE. Test two isolated partner contexts and an unrelated third account; concurrent invite redemption, pause union, stale approvals, stop races, retries and secret exclusion across all response channels.
- Recent-use avoidance covers last ten suggestions; favorites may be browser-local nonsensitive idea IDs. Dice is a local suggestion selector requiring wife review, never an automatic delivery. Branching gameplay is explicitly deferred and must not appear as implemented. Media, web push, achievements/levels and live voice remain documented follow-up scope.
